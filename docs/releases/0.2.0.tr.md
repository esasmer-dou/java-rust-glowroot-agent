# java-rust-glowroot-agent 0.2.0

Bu sürüm, mevcut Rust-Java REST entegrasyonunu değiştirmeden production gate ile doğrulanan Spring
Boot MVC desteği ekler. Java controller, handler, service, validation ve veritabanı kodu Java'da
kalmaya devam eder.

## Kullanıcı ne kazanır?

- Bytecode weaving yapmayan, düşük allocation kullanan tek Servlet filter içeren Spring Boot starter.
- HTTP `5xx` çağrıları için tam sayım ve başarılı istekler için sınırlı örnekleme.
- Tek sınırlı thread ve tekrar kullanılan tek h2 collector bağlantısı kullanan Rust exporter.
- Ek telemetri thread'i oluşturmayan mevcut Rust-Java REST entegrasyonu.
- Process RSS, thread, HTTP, native Dubbo, native Redis, reconnect, hata ve drop ölçümleri.
- SHA-256 kaynak doğrulaması olan Windows x64 ve Linux glibc x64 native kütüphaneleri.

## Spring Boot MVC hızlı başlangıç

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-glowroot-spring-boot-starter</artifactId>
  <version>0.2.0</version>
</dependency>
```

```properties
reactor.glowroot.enabled=true
reactor.glowroot.collector.address=http://glowroot-collector:8181
reactor.glowroot.agent.id=orders::pod-1
reactor.glowroot.application.name=orders-api
reactor.glowroot.http.sample-rate=256
reactor.glowroot.trace.capacity=0
```

Controller annotation'larını veya business API'lerini değiştirmeniz gerekmez. `0.2.0`, Spring
Servlet MVC destekler. WebFlux ile tam Glowroot Java metodu/JDBC instrumentation desteği vermez.

## Rust-Java REST hızlı başlangıç

Uyumlu `rust-java-rest:4.4.0` sürümünü kullanın ve `reactor.glowroot.*` property'lerini açın.
Framework mevcut Rust runtime'ını kullanır. Bu nedenle yeni telemetri thread'i eklenmez. Platformunuz
`-javaagent:key=value` biçimini zorunlu tutmuyorsa `java-rust-glowroot-agent:0.2.0` bootstrap JAR'ına
ihtiyacınız yoktur.

## Production sözleşmesi

Release workflow yalnız tag'in işaret ettiği commit production gate'i geçtiyse yayın yapar. Gate,
aynı Spring image içinde telemetri kapalı ve açık durumları karşılaştırır. Small JSON,
raw/precomputed JSON ve dynamic heavy JSON endpoint'leri c64 ve c256 seviyelerinde altı eşleştirilmiş
koşuyla ölçülür. Her hücre RPS, p99, hata, thread ve startup sınırlarını geçmelidir. Tam yükten sonra
eşit process yaşında yapılan bellek fazı, RSS ve cgroup için `+3 MiB` sınırını ayrıca uygular.

Bu tag commit'ine ait rapor, JSON özet ve steady-memory örnekleri release asset'i olarak eklenir.
Dosyalar yerel bir testten değil, başarılı Production Gate koşusundan alınır.

Ölçüm kanıtı, GitHub Packages erişimi, Kubernetes ayarları, tuning örnekleri ve desteklenmeyen
alanlar için README ile `docs/VALIDATION.tr.md` dosyasına bakın.
