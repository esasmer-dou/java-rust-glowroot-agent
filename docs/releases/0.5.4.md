# java-rust-glowroot-agent 0.5.4

[English](0.5.4.md) | [Turkish](0.5.4.tr.md)

`0.5.4` makes the performance qualification a mandatory release boundary. It keeps the bounded
collector reconnect behavior from `0.5.3`; Java APIs, business logic, REST ABI `29`, and Glowroot
ABI `6` do not change.

## What Users Get

- The release is tested with Rust-Java REST `4.6.2`, not an older framework checkout.
- Maven packages and GitHub assets cannot be published unless the exact release commit has a
  successful Production Gate run.
- The passing run must still contain non-expired Spring Boot and Rust-Java REST evidence artifacts.
- Spring MVC, WebFlux, and non-web fixtures are forced to use the same agent version as the release
  commit; an older locally cached or hard-coded agent cannot authorize the release.
- Each baseline/candidate pair uses the same automatically selected CPU group and reverses execution
  order between pairs. This keeps both variants on identical capacity and reduces time-order bias.
- Release A/B jobs run on pinned GitHub-hosted Linux images. Spring Boot and Rust-Java REST matrices
  run in parallel after the shared correctness job, so the gate no longer waits for one full matrix
  before starting the other.
- The measured application owns one complete physical CPU group. The load runner uses one logical CPU
  in the other group; collector and orchestration use its sibling. This bounded topology is written
  to the evidence artifact. A 30-second quiet-host window runs before the matrix; noisy or unstable
  runners fail instead of publishing performance claims.
- Telemetry-off/on comparisons keep the existing limits: useful `200` RPS loss no worse than `2%`,
  p99 regression no worse than `10%`, process/cgroup memory growth no more than `3 MiB`, no stable
  endpoint error-rate regression, and at most one exporter thread.
- The embedded REST protocol smoke uses a bounded curl request burst and must prove Web aggregate,
  gauge, slow-trace, Java-agent bootstrap, and collector-down fail-open behavior before release.

## Dependency

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-glowroot-spring-boot-starter</artifactId>
  <version>0.5.4</version>
</dependency>
```

Use Rust-Java REST `4.6.2` for the embedded runtime. Spring Boot applications use the DLL/SO
packaged by `0.5.4`. Do not combine this JAR with an older native file.

## Release Boundary

CI proves correctness, artifact bounds, and native provenance. The separate Production Gate proves
RSS, p99, useful RPS, error-rate, and thread-count non-regression on the exact release commit. A
release now requires both; a missing, failed, stale, or expired Production Gate stops publication
before Maven deploy and GitHub asset creation.
