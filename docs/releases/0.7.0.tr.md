# Java-Rust Glowroot Agent 0.7.0

[English](0.7.0.md) | [Türkçe](0.7.0.tr.md)

## Yayın Kontrolü

Yayın için aynı commit üzerindeki Production Gate'in geçmesi gerekir. Son ölçümler stable release'e
eklenen Spring ve REST raporlarında bulunur. Bu kontroller geçmeden tag üzerinden paket yayımlanamaz.
Micro ölçümü, diagnostic/JVM/full profillerinin bellek maliyetini doğrulamış sayılmaz.

19 Ekim 2026'da yapılan [düzeltme öncesi test](https://github.com/esasmer-dou/java-rust-glowroot-agent/actions/runs/39237537789)
reddedildi. Aşağıdaki değerler karşılaştırma içindir. Düzeltilmiş kaynağın sonucu değildir:

| Micro açık/kapalı karşılaştırması | REST, 3 eş koşu | Spring MVC, 6 eş koşu |
| --- | ---: | ---: |
| Boşta RSS farkı | +0,707 MiB, geçti | +6,144 MiB, geçmedi |
| Boşta container bellek farkı | +0,258 MiB, geçti | +6,418 MiB, geçmedi |
| Başarılı RPS, p99, hata ve ısınma | Geçti | Geçti |

İki bellek ölçümünde de sınır 3 MiB olarak kaldı. Başarısız ölçüm silinmedi ve geçti diye
sunulmadı. Sample 0.7.1 yayını, agent paketinin başarıyla yayımlanmasını bekler.
RSS incelemesinde agent kütüphanesinin yaklaşık 1,1 MiB yerleşik sayfası, daha büyük anonim bellek
farkından ayrıldı. Sınıf, heap ve smaps kanıtları test artifact'inde bulunur. Kalan farkı hangi JVM
veya allocator tahsisinin oluşturduğu bütünüyle kanıtlanmadı. Bu yüzden leak düzeltildi demiyoruz.
Aşağıdaki değişiklikler, kodda saptanan gereksiz başlangıç ve kaynak tutma işlerini kaldırır.

## Kullanımda Ne Değişti?

### Micro Başlangıcında Daha Az Kaynak

- Trace ayrıntıları kapalıysa MVC ayrıntı nesnesi oluşturulmaz. Sunucu adaptörleri ayarları tekrar
  okumak yerine aynı doğrulanmış ayarı kullanır.
- Rust, JVM başlangıç bilgilerini mevcut JNI çağrısında bir kez alır. Collector yeniden bağlanınca
  aynı küçük kayıt kullanılır. Exporter thread'i bu iş için JVM'e bağlanıp MXBean açmaz.
- OpenJ9/Linux üzerinde bootstrap VM ve boyutu sınırlı işletim sistemi dosyaları kullanılır.
  Başka JVM, SecurityManager veya belirsiz cgroup yerleşiminde standart yönetim yolu korunur.
- Metinler gizli değerlerden arındırılır. UTF-8 korunur. Kayıt mevcut gönderim ve bellek bütçesine
  sığar. Atlanan argümanlar işaretlenir. İstek, payload veya yanıt önbelleğe alınmaz.
- Teşhis çıktısı kullanılan yolu ve tutulan byte sayısını gösterir. Profil geçişleri korunur.
  Uygulamaya executor, yeni bağımlılık veya ABI değişikliği eklenmez. Bellek sınırı büyütülmez.

Plain Java scheduler, cache writer ve provider uygulamaları artık telemetriyi
`StandaloneTelemetry.startIfEnabled()` ile başlatabilir. Spring veya HTTP sunucusu gerekmez.
İş mantığı Java'da kalır. Sınırlı veri toplama, gönderim, yeniden bağlantı ve kaynak temizliği Rust'tadır.

| Uygulama | Kullanılacak özellik |
| --- | --- |
| Rust-Java REST 4.7.0 | İçindeki telemetriyi açın. Ek starter gerekmez. |
| Spring MVC veya WebFlux | Seçtiğiniz modülleri birlikte 0.7.0'a yükseltin. Ayarlar korunur. |
| Plain Java arka plan işi | `java-rust-glowroot-spring-runtime:0.7.0` ve açık işlem sınırı |
| Cache writer | İsteğe bağlı `java-rust-glowroot-cache-adapter:0.7.0` ve `ProjectionTelemetry.writer(...)` |
| Normal Apache Dubbo provider | Standalone yaşam döngüsü ve isteğe bağlı Dubbo SPI adaptörü |
| Minimal provider sample | `full-provider,glowroot` profilleri ve açık Dubbo 0.8.1 bağlantısı; tüm SPI filtre zinciri açılmaz |

İşlem adı sabit olsun. Örneğin `customer-refresh` kullanın. Müşteri kimliği veya payload kullanmayın.
İşlemleri başlangıçta bir kez kaydedin. Telemetriyi her çağrıda açıp kapatmayın.
`REACTOR_GLOWROOT_ENABLED=false` olduğunda native exporter başlatılmaz.

`NativeOperation.complete(started, false)` iş sonucu başarısızsa hata sayar. Her çağrıda yeni exception
üretmez. Projection adaptörü aynı sonucu döndürür, aynı exception'ı iletir. Executor veya yazma tekrarı eklemez.

Native yükleyici manifesti seçilen dosyanın yanından okur. Cache ve agent aynı classpath'teyken
birbirlerinin manifestini yanlışlıkla kullanmaz. Paket içindeki dosya veya açık native yol kullanılabilir.

## Geçiş ve Bellek Sınırı

Kullandığınız agent modüllerini birlikte yükseltin. Glowroot ABI 6 ve REST ABI 29 değişmez.
Standalone Windows x64 ve GLIBC 2.17 Linux x64 dosyaları temiz
`87d955f930f91eab812419b151c7749f80ad8522` kaynağından gelir. Windows derlemesi Visual Studio kullanmaz.
Native yolu açıkça veriyorsanız DLL/SO dosyasını da bu yayından alın.

Yayın için aynı commit üzerinde Spring ve REST micro profilinin açık/kapalı testleri gerekir.
Raporlar release'e eklenir. Sınırlar değişmez: başarılı RPS en fazla %2 düşebilir, p99 en fazla %10 artabilir.
Boşta normalize edilen RSS ve container bellek farklarının eş koşullu medyanı en fazla 3 MiB olabilir.
Mevcut hata ve thread kontrolleri de korunur. Bu sınır, yük altındaki her tepe ölçümünün 3 MiB altında
kalacağı anlamına gelmez. Diagnostic/JVM/full profilleri ayrıca ölçülmelidir.
Testi geçirmek için kuyruk, heap, worker veya timeout varsayılanları büyütülmez.

Maven paketi indirmek için `settings.xml` içinde geçerli `read:packages` token'ı kullanın. SSH yalnız Git içindir.
