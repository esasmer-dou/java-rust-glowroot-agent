# java-rust-glowroot-agent 0.3.0

`0.3.0`, uygulama çalışırken değiştirilebilen sınırlı telemetri profilleri ekler. HTTP programlama
modeli ve Java business kodu değişmez.

## Kullanıcı Ne Kazanır?

- Normal production kullanımı için küçük `reactor.glowroot.profile=micro` yüzeyini kullanabilirsiniz.
- JVM ölçümleri için geçici olarak `jvm`, açık SQL süreleri için `sql`, bu ikisi ve sınırlı hata
  stack bilgisi için `full` profiline geçebilirsiniz.
- Thread dump, heap histogram veya heap dump gerektiğinde `diagnostic` profilini yalnız yetkili ve
  kısa bir olay inceleme süresinde kullanabilirsiniz.
- `restoreConfiguredProfile()` ile başlangıç profiline dönebilirsiniz. Profile ait kuyruklar, SQL
  slotları, JNI referansları ve bekleyen export verisi metot dönmeden önce bırakılır.
- Toplama, protobuf encode, HTTP/2 gönderimi, reconnect ve kaynak bırakma işi `256 KiB` stack kullanan
  tek izole Rust thread'inde çalışır. Hyper veya application worker'ları kullanılmaz.
- Normal senkron Spring MVC isteklerinde agent state'i için nesne oluşturulmaz. Servlet attribute ve
  küçük gözlem nesnesi yalnız gerçek async redispatch akışında kullanılır.
- Aynı starter web olmayan Spring Boot worker'larında da kullanılabilir. Process/JVM ölçümleri, açık
  SQL süreleri ve yetkili tanılama işlemleri için Servlet MVC, Tomcat veya web application context
  gerekmez.
- Servlet koşulu yalnız isteğe bağlı MVC adaptöründedir. HTTP izlemeyi kapatıp çekirdek telemetriyi
  açık bırakmak için `reactor.glowroot.spring.enabled=false` kullanın. Native runtime'ı tamamen
  durdurmak için `reactor.glowroot.enabled=false` kullanın.

## En Küçük Ayar Seti

```properties
reactor.glowroot.enabled=true
reactor.glowroot.profile=micro
reactor.glowroot.collector.address=http://glowroot-collector:8181
reactor.glowroot.agent.id=orders::pod-1
reactor.glowroot.application.name=orders-api
```

Her Spring Boot uygulaması için şu dependency'yi ekleyin:

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-glowroot-spring-boot-starter</artifactId>
  <version>0.3.0</version>
</dependency>
```

Rust-Java REST `4.5.0` embedded runtime'ı zaten içerir. Starter gerekmez. Platform standardınız
`-javaagent` biçimini zorunlu tutuyorsa küçük `java-rust-glowroot-agent:0.3.0` bootstrap paketini
ekleyin.

## Uyumluluk

| Çalışma şekli | Zorunlu sözleşme |
| --- | --- |
| Rust-Java REST | `rust-java-rest:4.5.0`, REST ABI `29`, Glowroot ABI `3` |
| Spring Boot, web veya web olmayan | `java-rust-glowroot-spring-boot-starter:0.3.0`, Glowroot ABI `3` |
| Native platform | Temiz `rust-spring v4.5.0` revision'ından Windows x64 veya Linux glibc x64 |

DLL/SO dosyalarını sürümler arasında kopyalamayın. Startup; ABI, kaynak revision ve SHA-256
provenance bilgisini telemetri başlamadan doğrular.

## Production Sınırı

Profiller process genelinde geçerlidir. Profil değiştiren veya tanılama başlatan endpoint'leri kimlik
doğrulaması ve yetkilendirme ile koruyun. Release gate; exact release commit üzerinde Spring Boot ve
embedded REST davranışını, collector kapalıyken fail-open akışını, sınırlı memory kullanımını,
RPS/p99 sınırlarını, kesin `5xx` sayımını ve isteğe bağlı bootstrap'ı doğrular. Normal hücrelerde
non-2xx artışına izin verilmez. Bilinçli olarak doygun çalıştırılan embedded REST heavy JSON c256
hücresinde `0,02` yüzde puanlık non-inferiority marjı ve mutlak `%0,05` hata sınırı kullanılır.
Spring tutulan bellek kanıtı, bütün performans hücreleri tamamlandıktan sonra alınır. GC evresinin
`+3 MiB` kararını etkilememesi için iki varyanta da yalnız yük testinde kullanılan aynı tam GC ve
boşta bekleme penceresi uygulanır. Raporlar, native kaynak manifesti ve `SHA256SUMS` dosyası GitHub
Release'e eklenir.

Tam performans matrisi yalnızca dedicated `reactor-performance-native-linux` self-hosted runner
sınıfında çalışır. GitHub Actions orkestrasyonu ve release kararını yönetmeye devam eder. Exact
release commit için gerçek runner etiketleri ve native host preflight kanıtı kontrol edilir. Local
Docker/WSL hızlı gate'leri geliştirme sırasında kullanılır; bu release için onay veremez.

Runner, rastgele boş bir CPU seçmez. Önceden ölçülen ve ayrı fiziksel gruplara sabitlenen CPU rollerini kullanır. OpenJ9 için
16 sabit ısınma turu çalışır. JVM hâlâ hızlanıyorsa en fazla on altı sınırlı doğrulama turu eklenir.
Throughput eğilimi, dağılım, p99, hata ve bellek sınırları değiştirilmez.
