# Java-Rust Glowroot Agent 0.6.0

[English](0.6.0.md) | [Turkish](0.6.0.tr.md)

## Scheduler And Provider Visibility

This release adds non-web transaction boundaries without bytecode weaving or a Java telemetry
executor. The existing isolated Rust runtime owns counters, histograms, bounded traces and export.
Controllers, services and database transactions remain in Java.

| Work | Collector transaction type | Setup |
| --- | --- | --- |
| Spring scheduled task | `Scheduler` | Enable the agent; keep `@EnableScheduling` |
| Apache Dubbo provider | `Dubbo Provider` | Optional `java-rust-glowroot-spring-dubbo-adapter` |
| Generated Rust Dubbo provider | `Dubbo Provider` | Optional `java-rust-glowroot-spring-native-dubbo-adapter`, Rust Dubbo `0.7.0+` |
| Explicit Kafka/batch boundary | Your fixed type | Register and reuse `NativeOperation` |

```properties
reactor.glowroot.enabled=true
reactor.glowroot.profile=micro
reactor.glowroot.collector.address=http://glowroot-collector:8181
reactor.glowroot.agent.id=catalog::pod-1
reactor.glowroot.scheduler.enabled=true
reactor.glowroot.dubbo.provider.enabled=true
```

Select `Scheduler` or `Dubbo Provider` under **Transactions** after the first successful export.
`micro` includes transaction totals and latency aggregates; selected slow/error traces depend on
the profile and capacity. Normal Spring scheduler routing is preserved, including named schedulers.
Async providers are timed until business completion, not task submission. For reactive/`@Async`
scheduled work, define the explicit boundary inside the actual work or use `NativeOperation.observe`.

Use fixed names, never IDs, timestamps or request payloads. HTTP and operation descriptors share
the existing bounded route budget (maximum 64). Exhaustion drops new names, not the existing data.
The optional adapters do not install Apache Dubbo or the generated/native Dubbo runtime.

## Upgrade

Upgrade all agent artifacts to `0.6.0` and replace an explicitly configured DLL/SO with the file
from this release. Remove stale overrides if you want to use the verified packaged native file.
Glowroot ABI stays `6`; the additive operation API capability is `1`. An older ABI 6 native
library can still run HTTP telemetry but warns that it lacks non-web operation support.
Linux x64 retains GLIBC 2.17 compatibility. Windows x64 is built with cargo-xwin/Rust lld, not VS.
The HTTP-only Rust-Java REST integration remains coordinated with REST `4.6.2` (REST ABI 29).
Its published embedded native file does not acquire new operation APIs merely by adding this JAR.

Disabled telemetry does not start the exporter. No universal 1 MiB overhead or unchanged p99
is implied by API compatibility; select profiles and validate with the workload's memory budget.

Package downloads use Maven `settings.xml` with a valid `read:packages` token. SSH only covers Git.
