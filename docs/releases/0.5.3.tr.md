# java-rust-glowroot-agent 0.5.3

[English](0.5.3.md) | [Türkçe](0.5.3.tr.md)

`0.5.3`, Glowroot Central'ın kalıcı HTTP/2 bağlantısını 20 dakikalık sınırda yenilediği anda
kaybolabilen transaction interval sorununu düzeltir. Java controller, service, validation, Dubbo
client ve business logic kullanımı değişmez. Glowroot native ABI `6` olarak kalır.

## Neler Değişti?

| Aşama | Yeni davranış |
| --- | --- |
| Snapshot öncesi | Exporter bağlantıyı 15 dakika sonra yeniler. Sayaçları almadan önce bağlantının hazır olduğunu kontrol eder. |
| Bağlantı kapanma yarışı | Exporter yeniden bağlanır, collector init gönderir ve aynı protobuf byte dizisini tekrar yollar. |
| Central onayından önce | Tek ve sınırlı aggregate batch Rust tarafında kalır. Gönderilmiş sayılmaz. |
| Uzun kesinti | Pending batch büyümez. Yeni transaction'lar önceden ayrılmış sayaçlarda birikir. |
| Toparlanma | Central onayı batch'i serbest bırakır. `pending_aggregate_transactions` yeniden sıfır olur. |

## Spring Boot Dependency

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-glowroot-spring-boot-starter</artifactId>
  <version>0.5.3</version>
</dependency>
```

`0.5.3` içinde gelen DLL/SO dosyasını kullanın. Ortak image katmanında eski `0.5.2` native dosyasını
bırakmayın.

## Production Kontrolü

Şu diagnostics alanlarını izleyin:

- `collector_rotations` yaklaşık 15 dakika sonra artmalıdır.
- Bağlantı kapanma yarışı veya geçici failover sırasında `collector_request_retries` artabilir.
- Toparlanma sonrasında `pending_aggregate_transactions` yeniden sıfır olmalıdır.
- Başarıyla toparlanan rotasyonda `dropped_transactions`, `dropped_intervals` ve `last_error_code`
  artmamalıdır.

Retry durumu bellekte ve sınırlıdır. Central bağlantı yenilemesini ve geçici transport hatalarını
korur. Process crash sonrasında kalıcı kuyruk sağlamaz. Böyle bir garanti disk WAL ve farklı bir
footprint sözleşmesi gerektirir.

## Doğrulama

Native gate, ilk aggregate body'yi okuduktan sonra onay göndermeden kapanan yerel bir HTTP/2
collector kullanır. Yeni bağlantı byte-byte aynı payload'ı alır. Dropped transaction sayacı artmaz.
Linux binary'leri `glibc 2.17` symbol sınırını korur.
