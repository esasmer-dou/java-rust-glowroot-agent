# Java-Rust Glowroot Agent 0.6.0

[English](0.6.0.md) | [Turkish](0.6.0.tr.md)

**Stable sürüm yayımlandı.** Maven paketleri ve aynı sürümün native dosyaları,
[aynı commit'in Production Gate kontrolünden](https://github.com/esasmer-dou/java-rust-glowroot-agent/actions/runs/38927189449) geçti.

## Ölçümün Kapsamı

Her runtime için üç bağımsız çift çalıştırıldı. Micro profilinde küçük/raw JSON, c64/c256
ile ölçüldü. RPS, p99 ve hata kontrolleri değişmeyen eşiklerle geçti. Heavy JSON, Servlet
motorları, WebFlux, web olmayan uygulama, profil geçişleri ve native provenance da doğrulandı.

| Runtime | Idle RSS medyan farkı | Container medyan farkı | Ek OS thread |
| --- | ---: | ---: | ---: |
| Spring Boot | +1,574 MiB | +1,914 MiB | 1 |
| Rust-Java REST | +0,317 MiB | +0,008 MiB | 1 |

Bu değerler agent kapalı/açık farkıdır. Uygulamanın toplam belleği veya iki sürüm arasındaki
kazanç değildir. Tek bir Spring çiftinde +4,500 MiB görüldü. Yük sırasında daha büyük geçici
farklar da oluştu. 3 MiB kuralı, benchmark'a özel GC ve idle sonrasındaki çiftlerin medyanına
uygulanır. Her anda 3 MiB altında kalma garantisi değildir. Bunu pod bellek limiti olarak
kullanmayın. Ayrıntılı profiller için ayrıca bütçe ayırın. Gereksiz diagnostic başlangıcı
kaldırıldı. Ancak bu düzeltmenin tek başına yük altında büyük RSS kazancı sağladığı, eşleştirilmiş
yerel karşılaştırmada kanıtlanmadı. JVM, JIT ve allocator durumu da sonucu etkiler.

## Micro Profilinde Bellek

Micro profilinde diagnostic thread ölçümleri kapalıysa ilgili MXBean oluşturulmaz.
Bu nesne yalnız diagnostic ölçüm gerektiğinde alınır. Diagnostic kapatılınca uygulamanın
önceki sayaç ayarları geri yüklenir ve agent'ın bean referansları bırakılır.
JVM'in yüklediği sınıflar ve JIT belleği profil değişince hemen silinmeyebilir.
Kuyruk kapasitesi, tüm uygulamanın RSS sınırı değildir.

Bellek kontrolü Linux smaps, cgroup, JVM pool ve warmup tur sayılarını da saklar.
Böylece native dosya ile heap, JIT ve allocator farkları ayrı incelenebilir.
Bu ölçümler benchmark uygulamasındadır. Production istek yoluna eklenmez.
Micro profilinin 3 MiB RSS/container sınırı değiştirilmemiştir.

## Scheduler Ve Provider Görünürlüğü

Bu sürüm web dışındaki işlemleri de ölçer. Bytecode weaving veya Java telemetri executor'ı eklenmez.
Sayaç, histogram, sınırlı trace ve gönderim izole Rust runtime'ında kalır. İş kodu Java'da çalışır.

| İş | Collector işlem türü | Kurulum |
| --- | --- | --- |
| Spring zamanlanmış iş | `Scheduler` | Agent'ı açın; `@EnableScheduling` kalsın |
| Apache Dubbo provider | `Dubbo Provider` | İsteğe bağlı `java-rust-glowroot-spring-dubbo-adapter` |
| Generated Rust Dubbo provider | `Dubbo Provider` | `java-rust-glowroot-spring-native-dubbo-adapter`, Rust Dubbo `0.7.0+` |
| Açık Kafka/batch sınırı | Seçtiğiniz sabit tür | Bir kez `NativeOperation` kaydedin |

```properties
reactor.glowroot.enabled=true
reactor.glowroot.profile=micro
reactor.glowroot.collector.address=http://glowroot-collector:8181
reactor.glowroot.agent.id=catalog::pod-1
reactor.glowroot.scheduler.enabled=true
reactor.glowroot.dubbo.provider.enabled=true
```

İlk başarılı gönderimden sonra **Transactions** ekranında `Scheduler` veya `Dubbo Provider` seçin.
`micro`, çağrı toplamlarını ve süre dağılımlarını içerir. Yavaş/hatalı trace ayrıntıları profile ve
kapasiteye bağlıdır. İsimle seçilen scheduler dahil mevcut Spring yönlendirmesi korunur.
Async provider süresi iş tamamlanınca biter. Reactive veya `@Async` scheduler işinde sınırı asıl işin
içinde tanımlayın. `CompletionStage` için `NativeOperation.observe` kullanabilirsiniz.

İşlem adları sabit olmalıdır. Kimlik, saat veya payload kullanmayın. HTTP ve iş tanımları mevcut
sınırlı bütçeyi paylaşır: en fazla 64 slot. Limit dolunca yeni ad atlanır; bellek büyütülmez.
İsteğe bağlı adaptörler uygulamaya Apache Dubbo veya native Dubbo runtime bağımlılığı taşımaz.

## Yükseltme

Tomcat'in yalnız toplamları ölçen yolu, kullanılmayan diagnostic attribute ve sampler işini atlar.
İstek/hata sayıları ve route adları değişmez. Diagnostic profile geçildiğinde tam kayıt yolu kullanılır.
Java iş API'sinde değişiklik gerekmez.

Tüm agent paketlerini `0.6.0` yapın. Açık native dosya yolu kullanıyorsanız DLL/SO'yu da bu sürümle
değiştirin. Paket içindeki dosyayı kullanmak için eski yol ayarını kaldırın. Glowroot ABI `6` kalır.
Yeni işlem API desteği ayrıca `1` olarak kontrol edilir. Eski ABI 6 dosyası HTTP ölçümünü sürdürebilir;
web dışı işlem desteği olmadığını başlangıçta bildirir.

Linux x64 için GLIBC 2.17 uyumluluğu korunur. Windows x64, Visual Studio olmadan derlenir.
HTTP amaçlı Rust-Java REST entegrasyonu REST `4.6.2` ve REST ABI 29 ile uyumludur. Yalnız agent JAR'ını
eklemek REST paketindeki eski native dosyaya yeni işlem API'si kazandırmaz.

Agent kapalıysa exporter başlamaz. Her yük için 1 MiB ek bellek veya değişmeyen p99 garantisi yoktur.
Profili servisinizin bellek bütçesi ve gerçek yüküyle doğrulayın.

Maven indirmeleri için `settings.xml` içinde geçerli `read:packages` token gerekir. SSH yalnız Git içindir.
