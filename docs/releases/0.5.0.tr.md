# java-rust-glowroot-agent 0.5.0

[English](0.5.0.md) | [Türkçe](0.5.0.tr.md)

`0.5.0`, sınırlı HTTP telemetrisini mevcut Glowroot transaction ekranlarında görünür hale getirir.
İsteğe bağlı trace ayrıntısı sınırlı kalır.

## Kullanıcıya Ne Sağlar?

- Tamamlanan her HTTP isteği **Average**, **Percentile**, **Throughput** ve **Errors** ekranlarına tam
  olarak bir kez eklenir.
- Transaction type `Web` olur. `/orders/*` gibi yalnız route kalıbını içeren adlar ve Glowroot'un
  beklediği `http request` root timer kullanılır.
- `reactor.glowroot.http.sample-rate` yalnız isteğe bağlı trace ayrıntısını kontrol eder. Başarılı
  istekleri endpoint toplamlarından çıkarmaz.
- Route sayısı sınırı aşılırsa fazla route'lar kaybolmaz. `<route-limit-exceeded>` altında toplanır.
- Startup sırasında aktif Spring HTTP adaptörü görünür. Örnek:

```text
Java-Rust Glowroot HTTP telemetry active: adapter=tomcat-valve, transaction-type=Web
```

Tomcat, Jetty, Undertow, taşınabilir Spring MVC ve WebFlux ayrı ve isteğe bağlı adaptör yollarını
korur. Java uygulama modeli ile mevcut Glowroot Central/Cassandra deployment'ı değişmez.

## Uyumluluk

| Bileşen | Sürüm veya sözleşme |
| --- | --- |
| Agent paketleri | `0.5.0` |
| Rust-Java REST | `4.6.0` |
| REST native ABI | `29` |
| Glowroot native ABI | `4` |
| Linux native tabanı | GLIBC `2.17` |

Bu sürümdeki bütün Java modüllerini ve DLL/SO dosyasını birlikte kullanın. ABI `3` binary startup
sırasında reddedilir. Aynı process içinde `java-rust-cache` de yükleniyorsa `0.7.6` kullanın.

## K8s Doğrulaması

1. Eşleşen `0.5.0` paketini ve native dosyayı deploy edin.
2. Startup satırında doğru adaptör adını ve `transaction-type=Web` değerini doğrulayın.
3. En az iki eşleşen route'a trafik gönderin.
4. Bir export aralığı bekleyin. Varsayılan süre 60 saniyedir.
5. Glowroot **Transactions** ekranında **Web** seçin. Route toplamlarını gönderdiğiniz isteklerle
   karşılaştırın.

Windows DLL ve Linux SO, temiz `rust-spring v4.6.0` revision
`0ec9c9df091f225d3e78e6ced4f9b118dd9ba73c` üzerinden üretildi. Release workflow, publish öncesinde
SHA-256 provenance bilgisini ve GLIBC 2.17 sembol sınırını doğrular.
