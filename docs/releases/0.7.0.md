## What Changes for You

### Bounded HTTP Completion Path

- Registered routes use one immutable table snapshot. Publishing a new route is synchronized;
  existing route lookup takes no lock and allocates no per-request entry. Overflow stays bounded.
- JNI supplies nanoseconds directly to Rust aggregate counters. Optional trace construction stays
  on the selected trace path. Counts, errors, latency buckets and trace selection are unchanged.
- Standalone exporter transport dependencies are optimized for binary size. Agent/JNI hot code
  retains speed optimization. No queue, thread or executor is added.
- The new candidate must pass the same memory/RPS/p99 gate. A local same-process probe separated
  almost-flat native request stacks from growing resident Java heap; it does not prove that all
  heap residency belongs to the agent or that the optimizations recover that entire difference.

### Smaller Micro Startup Surface

- MVC does not instantiate its trace enricher when trace details are disabled. Server adapters share
  one validated configuration instead of reparsing all properties.
- Rust captures JVM startup metadata once on the existing JNI caller. Collector reconnect borrows
  that bounded immutable snapshot, without attaching the exporter thread to initialize MXBeans.
- OpenJ9/Linux uses bootstrap VM arguments and bounded OS/cgroup reads. A security manager, another
  JVM, or an ambiguous cgroup mount keeps the public management-bean fallback.
- Snapshot text is redacted, UTF-8 safe, and limited by the export envelope and the existing bridge
  budget. Omitted arguments are marked. No request, payload, or response is cached by this change.
- Diagnostics report the snapshot source and retained size. Diagnostic/profile transitions keep
  their existing behavior. No application executor, dependency, ABI, or memory ceiling is added.

Plain Java schedulers, cache writers and providers can now start telemetry explicitly with
`StandaloneTelemetry.startIfEnabled()`. Spring and an HTTP server are not required.
Java keeps business logic. Rust keeps bounded aggregation, export, reconnect and resource cleanup.

| Application | Add or use |
| --- | --- |
| Rust-Java REST 4.7.1 | Enable its embedded telemetry; no extra starter |
| Spring MVC or WebFlux | Matching 0.7.0 starter/adapter; existing configuration stays valid |
| Plain Java background worker | `java-rust-glowroot-spring-runtime:0.7.0` and an explicit operation |
| Cache writer | Optional `java-rust-glowroot-cache-adapter:0.7.0` and `ProjectionTelemetry.writer(...)` |
| Normal Apache Dubbo provider | Standalone lifecycle plus optional Dubbo SPI adapter |
| Minimal provider sample | `full-provider,glowroot` profiles and the explicit Dubbo 0.8.1 dispatcher hook; no full SPI filter chain |

Use fixed operation names such as `customer-refresh`, never a customer ID or a payload.
Register operations once. Keep the telemetry handle open for the application lifetime.
Set `REACTOR_GLOWROOT_ENABLED=false` to avoid native startup and exporter resources.

`NativeOperation.complete(started, false)` counts a business rejection with a reused stackless marker,
not a new exception per call. Projection observation preserves the original result/exception and adds no executor or retry.

The native loader reads provenance beside the selected binary. An unrelated cache manifest can no longer
shadow the agent manifest when both libraries share a classpath. Packaged and explicitly selected native files remain supported.

## Upgrade and Memory Boundary

Upgrade all selected agent modules together. Glowroot ABI stays 6; REST ABI stays 29.
Standalone Windows x64 and GLIBC 2.17 Linux x64 native files come from clean source
`b98f791d9889c67dc10e537757fc3c0927ed0bbe`. Windows uses cargo-xwin, not Visual Studio.
Use this release's DLL/SO if your deployment overrides the native path.

Publication requires exact-commit Spring and REST micro-profile off/on gates. Their reports and summaries
are attached to this release. The unchanged bounds are -2% useful RPS, +10% p99 and +3 MiB steady
paired-median RSS/cgroup memory, with the existing error/thread checks. This is not an always-below-3-MiB
load-peak guarantee. Diagnostic/JVM/full profiles and application-specific workloads have separate costs.
No queue, heap, worker or timeout default is raised to pass a test.

Download Maven packages with a valid `read:packages` token in `settings.xml`. SSH authenticates Git only.
