# java-rust-glowroot-agent 0.5.2

[English](0.5.2.md) | [Türkçe](0.5.2.tr.md)

`0.5.2`, Spring için sınırlı tanılama yolunu tamamlar. Java business logic, controller, service,
validation ve Dubbo client kodunuz değişmez. Java sınırı küçük metadata değerlerini iletir. Protobuf
encode, kuyruklar, hata stack'inin okunması, collector bağlantısı, canlı JVM komutları, reconnect ve
kaynak bırakma izole Rust exporter üzerinde çalışır.

## Kullanıcı Ne Elde Eder?

| Alan | Glowroot'ta görünen sonuç |
| --- | --- |
| Endpoint ekranları | Tam route sayısı, Average, Percentile, Throughput ve Errors |
| Yavaş/hatalı trace | HTTP metodu, yanıt kodu, `http request`, controller süresi/satırı ve sınırlı thread sayaçları |
| Spring Dubbo consumer | `dubbo consumer` süresi, operasyon, çağrı sayısı ve hata sayısı |
| Hata | Varsa gerçek exception sınıfı/mesajı/stack'i; yoksa `HTTP status 5xx` |
| Canlı JVM | Thread dump, OpenJ9 heap histogram/dump, Force GC, MBean ağacı ve maskelenmiş System properties |
| Environment | Host, CPU, fiziksel bellek, işletim sistemi, process, Java/OpenJ9, maskelenmiş JVM argümanları, dump dizini ve agent sürümü |

Yalnız Dubbo çağıran bir servis için SQL ayarı gerekmez. Agent HTTP body, query/header değeri, Dubbo
argümanı/sonucu veya işletim sistemindeki bütün environment variable değerlerini bellekte tutmaz.

## Spring Boot Kurulumu

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-glowroot-spring-boot-starter</artifactId>
  <version>0.5.2</version>
</dependency>
```

Sorun incelerken yalnız bir pod üzerinde diagnostic profili kullanın:

```yaml
env:
  - name: REACTOR_GLOWROOT_ENABLED
    value: "true"
  - name: REACTOR_GLOWROOT_PROFILE
    value: "diagnostic"
  - name: REACTOR_GLOWROOT_SPRING_ENABLED
    value: "true"
  - name: REACTOR_GLOWROOT_COLLECTOR_ADDRESS
    value: "http://glowroot-central:8181"
  - name: REACTOR_GLOWROOT_AGENT_ID
    value: "nmc-store-common::$(POD_NAME)"
  - name: REACTOR_GLOWROOT_HTTP_SAMPLE_RATE
    value: "256"
  - name: REACTOR_GLOWROOT_TRACE_CAPACITY
    value: "8"
  - name: REACTOR_GLOWROOT_TRACE_SLOW_THRESHOLD_MS
    value: "500"
```

`sample-rate=256` yalnız normal başarılı isteklerin isteğe bağlı trace ayrıntısını örnekler. Endpoint
toplamlarını azaltmaz. Yavaş istekler ve hatalar kendi kurallarıyla seçilir. Trace kuyruğu sekiz kayıt
ile sınırlı kalır.

## Beklenen Startup Kanıtı

```text
Java-Rust Glowroot native telemetry active: abi=6, profile=diagnostic, application=nmc-store-common
Java-Rust Glowroot HTTP telemetry active: adapter=jetty-request-log, transaction-type=Web
Java-Rust Glowroot live diagnostics connected: agent-id=nmc-store-common::pod-name
```

İlk satır JAR/SO ABI çiftinin çalıştığını gösterir. İkinci satır HTTP tamamlanma adaptörünü doğrular.
Üçüncü satır Glowroot Central'ın canlı JVM komutu gönderebildiğini gösterir. Normal aggregate ve canlı
komutlar ayrı HTTP/2 bağlantıları kullanır.

## Uyumluluk

| Bileşen | Gerekli sürüm |
| --- | --- |
| Java | `21`; ana JVM Semeru OpenJ9'dur |
| Agent | `0.5.2` |
| Glowroot native ABI | `6` |
| Uyumlu Rust-Java REST | `4.6.1` |
| Linux x64 | `glibc 2.17` veya daha yeni |
| Apache Dubbo adaptörü | `3.3.0-beta.4` ile derlenir; uygulamadaki runtime'ı kullanır |

Bu release ile gelen DLL/SO dosyasını kullanın. `0.5.2` JAR dosyasını `0.5.1` native kütüphanesiyle
veya eski bir Rust-Java REST paketiyle birleştirmeyin.

## Operasyon Sınırı

Thread dump sınırlıdır. Heap histogram en fazla 4096 class ve 1 MiB yanıt üretir. Heap dump yine tek
seferlik yüksek JVM allocation ve disk dosyası oluşturabilir. Canlı işlemleri olay sırasında bir pod
üzerinde çalıştırın. İşiniz bitince `micro` profile veya servisin normal profiline dönün.

Uygulama log weaving ve genel request payload toplama bu sürümde bilinçli olarak yoktur. Aranması
gereken business değerleri için maskelenmiş uygulama log'u veya sınırlı domain metriği kullanın.
